# تفعيل حسابات المدرسة والبيانات المشتركة

الإصدار 0.7 يحتاج مشروع Firebase خاص بالمدرسة. لا تضع كلمة مرور المدير أو مفاتيح حساب الخدمة في الملفات أو في GitHub. إعداد تطبيق الويب `firebaseConfig` الظاهر في Firebase Console صالح للاستخدام في المتصفح؛ حماية البيانات تعتمد على قواعد الوصول أدناه.

## ١. تجهيز Firebase

1. افتح https://console.firebase.google.com/ وأنشئ مشروعاً، ثم أضف تطبيق **Web** وانسخ `apiKey`, `authDomain`, `projectId`, `storageBucket`, `appId`.
2. من **Authentication → Sign-in method** فعّل **Email/Password**. من **Settings → Authorized domains** أضف اسم نطاق Railway الذي يستعمله الموقع، وأضف `localhost` للتطوير المحلي. إذا كان لديك نطاق مخصص فأضفه أيضاً.
3. أنشئ **Cloud Firestore** في وضع الإنتاج. افتح **Rules** والصق كامل محتوى `project/firestore.rules` واضغط **Publish**.
4. أنشئ **Cloud Storage** إذا تريد صور القنوات وملفات المحاضرات. قد يتطلب إنشاء حاوية Storage خطة Blaze. الصق `project/storage.rules` في تبويب **Rules** واضغط **Publish**. عند طلب صلاحية ربط قواعد Storage بـ Firestore وافق عليها، فالقواعد تستعلم عن بيانات الأستاذ والقنوات من Firestore.

**مهم:** لا تُطلق الموقع بحسابات حقيقية قبل نشر القاعدتين. بدون Storage تستطيع كتابة منشورات نصية وإضافة محاضرات بلا ملفات.

## ٢. متغيرات Railway

في خدمة الموقع داخل Railway افتح **Variables** وأضف القيم التالية من إعداد تطبيق Web في Firebase، بالتهجئة نفسها:

```dotenv
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=...
VITE_FIREBASE_PROJECT_ID=...
VITE_FIREBASE_STORAGE_BUCKET=...
VITE_FIREBASE_APP_ID=...
```

ارفع الملفات الجديدة إلى مستودع GitHub بالمسارات نفسها: ملفات `project/`، وملف `Dockerfile` في جذر المستودع. يحتفظ جذر المستودع أيضاً بـ `Caddyfile` و`.dockerignore` الموجودين من النسخة السابقة. Railway يبني التطبيق تلقائياً بعد تحديث GitHub؛ إذا كانت المتغيرات قد أُضيفت بعد آخر بناء فأعد **Redeploy**. الـ Dockerfile يمرر متغيرات `VITE_` إلى عملية البناء.

ملف `index.html` الموجود في جذر نسخة المعاينة القديمة يعرض نسخة تجريبية منفصلة؛ افتح **رابط Railway** لاختبار الحسابات المشتركة. ويمكن تشغيل المشروع محلياً من مجلد `project`: انسخ `.env.example` إلى `.env.local` وأدخل قيم Firebase ثم `npm ci` و`npm run dev`.

## ٣. إنشاء أول حساب إدارة

1. افتح الموقع على Railway، وسجّل حساباً بالبريد الذي ستستعمله للإدارة؛ سيكون حساب طالب موقتاً. افتح رسالة تأكيد البريد واضغط رابط التأكيد ثم ارجع للموقع وحدّث الصفحة.
2. في Firebase Console افتح **Authentication → Users** وانسخ **User UID** لهذا الحساب.
3. افتح **Firestore Database → Data** وأنشئ collection باسم `admins`، وأنشئ document يكون **Document ID** فيه نفس UID حرفياً. أضف الحقل `name` من نوع string، مثل `إدارة المدرسة`.
4. حدّث صفحة الموقع. ستظهر لوحة الإدارة. إنشاء وثيقة المدير بهذه الطريقة يتم مرة واحدة عبر Firebase Console ولا يوجد زر عام لترقية الحسابات إلى مدير.

## ٤. اعتماد أستاذ وتجربة طالب

1. من حساب المدير افتح **الأساتذة → إضافة أستاذ**، واكتب اسم الأستاذ وبريده الصحيح والمواد المسموح بها مفصولة بفاصلة، ثم احفظ.
2. الأستاذ يفتح الموقع ويسجّل **بنفس البريد حرفياً** ويختار كلمة مروره بنفسه. بعد تأكيد البريد وتحديث الصفحة، تظهر له صلاحية الأستاذ. لا ترسل له كلمة مرور من عندك.
3. الأستاذ ينشئ قناة لمادة معتمدة ويختار اسم كتابها ومعرّف القناة؛ بعدها يضيف منشوراً أو محاضرة. الطالب ينشئ حساباً مختلفاً، يبحث عن معرّف القناة وينضم إليها.
4. جرّب بحسابين مختلفين على جهازين للتأكد من ظهور البيانات فوراً. إذا عطّلت دعوة الأستاذ أو أزلت مادة، ترفض قواعد Firebase نشره الجديد فوراً؛ حدّث الصفحة لتتحدث واجهته.

**ملاحظات:** بيانات المعاينة القديمة المحفوظة داخل المتصفح لا تنتقل تلقائياً إلى Firebase. الروابط التي تنشئها Firebase للملفات تحمل رمز وصول؛ من يملك رابط الملف يستطيع فتحه، لذا لا تنشر مواد سرية بهذه النسخة. مراقبة الطلاب، نسخ البيانات الاحتياطية، وتنظيم نقل البيانات القديمة مراحل لاحقة.
